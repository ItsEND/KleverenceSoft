# KleverenceSoft

Решение тестового задания из трёх независимых задач:

1. компрессия и декомпрессия строк;
2. потокобезопасный статический счётчик;
3. приведение записей лог-файла к единому формату.


## Сборка

Из корневого каталога репозитория:

```text
dotnet build KleverenceSoft.sln
```

## Тестирование

```text
dotnet test KleverenceSoft.sln
```

Тестами проверяются:

- компрессия одиночных символов и групп, включая количества из нескольких цифр;
- декомпрессия и восстановление исходной строки после полного цикла преобразований;
- отсутствие потерянных обновлений при параллельной записи в счётчик;
- совместное выполнение чтений и записей;
- разбор обоих форматов логов;
- нормализация уровней логирования;
- отклонение записей с некорректными датой, временем или уровнем;
- обработка отсутствующего вызывающего метода, неразрывных пробелов и символа `|` внутри сообщения;
- формирование выходной строки с разделителями-табуляциями.

## Задача 1 — компрессия строк

Последовательность одинаковых строчных букв латинского алфавита заменяется буквой и количеством её повторений. Для одиночного символа количество не записывается.

Пример:

```text
aaabbcccdde -> a3b2c3d2e
```

Обратное преобразование восстанавливает исходную строку:

```text
a3b2c3d2e -> aaabbcccdde
```

Количество повторений может состоять из нескольких цифр, например `a12`.

Алгоритмы выполняют один последовательный проход по входным данным. Временная сложность компрессии — `O(n)`, декомпрессии — `O(m)`, где `m` — длина восстановленной строки.

## Задача 2 — потокобезопасный счётчик

Для синхронизации используется `ReaderWriterLockSlim`:

- несколько читателей могут получать значение одновременно;
- писатели изменяют значение последовательно;
- во время записи читатели ожидают освобождения блокировки.



## Задача 3 — стандартизация лог-файлов

Программа читает входной файл построчно. Корректные записи преобразуются и сохраняются в основной выходной файл, а некорректные записываются без изменения в отдельный файл проблем.

### Запуск

Без аргументов используются файлы `input.txt`, `output.txt` и `problems.txt` в текущем рабочем каталоге:

```text
dotnet run --project Tasks/Task3/Task3.csproj
```

Пути можно передать аргументами в следующем порядке:

```text
dotnet run --project Tasks/Task3/Task3.csproj -- <inputPath> <outputPath> <problemsPath>
```

Пример:

```text
dotnet run --project Tasks/Task3/Task3.csproj -- data/input.txt data/output.txt data/problems.txt
```

Каждый неуказанный путь заменяется соответствующим значением по умолчанию: `input.txt`, `output.txt` или `problems.txt`.

### Поддерживаемые входные форматы

Формат 1:

```text
10.03.2025 15:14:49.523 INFORMATION Версия программы: '3.4.0.48729'
```

Формат 2:

```text
2025-03-10 15:14:51.5882| INFO|11|MobileComputer.GetDeviceId| Код устройства: '@MINDEO-M40-D-410244015546'
```

### Выходной формат

Поля разделяются символом табуляции:

```text
Дата	Время	Уровень	ВызвавшийМетод	Сообщение
```

Пример результата:

```text
10-03-2025	15:14:49.523	INFO	DEFAULT	Версия программы: '3.4.0.48729'
10-03-2025	15:14:51.5882	INFO	MobileComputer.GetDeviceId	Код устройства: '@MINDEO-M40-D-410244015546'
```

Уровни логирования нормализуются следующим образом:

| Входное значение | Выходное значение |
|---|---|
| `INFO`, `INFORMATION` | `INFO` |
| `WARN`, `WARNING` | `WARN` |
| `ERROR` | `ERROR` |
| `DEBUG` | `DEBUG` |

Если вызывающий метод отсутствует, используется значение `DEFAULT`. Время и сообщение сохраняются в исходном формате.

### Обработка некорректных записей

Запись считается некорректной, если она не соответствует ни одному поддерживаемому формату, содержит неправильные дату или время либо неподдерживаемый уровень логирования.

Такая строка записывается в файл, заданный параметром `problemsPath`, в исходном виде.

### Формат даты

Текст задания требует выходной формат `DD-MM-YYYY`, хотя приведённые в нём примеры используют `YYYY-MM-DD`. Реализация следует текстовому требованию и формирует дату в формате `DD-MM-YYYY`.
